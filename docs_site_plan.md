# Plan: DS30 Docs, a standalone Docusaurus documentation site

Status: planning only. Written on branch `docs/ds30-docs-site` of `gtm_analyzer_app`. The implementation happens in a **new repository** (suggested name: `ds30-docs`), not here.

## 1. Goal
A new, smaller project that documents DS30 (GTM Architecture & UPD Analyzer) with a **user guide first** and project/technical docs second, with screenshots and video, on its own domain. It uses the same stack as Polaris (Docusaurus) so the content can be added to Polaris later with little rework.

It is not a Polaris fork. Polaris is kept in the new repo only as a reference (section 3).

## 2. Decisions already made
- **Languages:** pt-BR (default, source of truth) + en + es via Docusaurus i18n.
- **Hosting:** Cloud Run + IAP restricted to `dp6.com.br`, on a new domain separate from `polaris.dp6.io`. Same nginx/Dockerfile/Workload Identity deploy pattern as Polaris.
- **Video:** both. Short clips are self-hosted with `<video>`. Long walkthroughs are unlisted YouTube/Drive embeds.
- **Deploys are human-only**, as in this repo's `CLAUDE.md`.

## 3. Polaris example in the new repo
Copy the Polaris example into the new repo as read-only reference material, for example `reference/polaris-heap-main/`.
- Source: `Docs/polaris-heap-main/polaris-heap-main/` (the zip is nested one level; use the inner folder).
- Leave out all `*:Zone.Identifier` files (Windows download artifacts), `node_modules/` and `build/`.
- Do not wire it into the Docusaurus build or the sidebars. Add `reference/` to `.gitignore` for Docker builds, or exclude it in `.dockerignore`.
- Add a short `reference/README.md` saying where it came from, the date, and that it is a snapshot, not a dependency.
- Its job: a place to copy config from (`docusaurus.config.js`, `sidebars.js`, `Dockerfile`, `nginx.conf`, `deploy.yml`, `scripts/check-docs.sh`, `CLAUDE.md`, `MANIFESTO.md`) and a way to check that DS30 content still fits Polaris's rules.

## 4. What to copy from Polaris, and what not to
Copy:
- Docusaurus ^3.10 + `@docusaurus/faster`, React 19, npm, Node >= 20.
- `onBrokenLinks: 'throw'`, `noIndex`, dark-by-default theme with CSS tokens (from `Docs/DP6 Design System - Para usar com IA.md`).
- Per-area autogenerated sidebars. Each section's `_category_.json` needs `label`, `position` and a `generated-index` link with a **unique slug**. Do not create a root `_category_.json` for an area.
- Frontmatter on every page: `title`, `description`, `sidebar_position`.
- File names in kebab-case without accents. Accents only in the `label`.
- `scripts/check-docs.sh` (drop the client-data checks) run in a PR job.
- Dockerfile (nginx:alpine, port 8080), `nginx.conf` with `X-Robots-Tag`, and the `deploy.yml` skeleton.

Do not copy: the Node sidecar (request forms, OAuth), the `catalogo-cards` plugin, the AuthGate, the Polaris home. IAP handles access.

Polaris has **no pattern for images or video**. That part is designed here (section 6).

## 5. Site structure
```
docs/
  guia-do-usuario/           # PRIORITY, for analysts, task-based, with media
    primeiros-passos/        # sign-in, projects, sharing
    area-de-trabalho/        # one page per workspace tab
    ingestao-de-dados/       # GTM JSON upload, live Google query, ObservePoint crawl
    texto-com-ia/            # AI-generated narrative fields
    gerando-o-diagnostico/   # Google Doc generation
    solucao-de-problemas/    # e.g. generation timeout (504 may still create the doc), OAuth errors
  documentacao-do-projeto/
    visao-geral-e-arquitetura/   # mermaid diagrams, request flow
    desenvolvimento/             # getting started, tests, git and deploy rules
    integracoes/                 # Apps Script, Google Ads, ObservePoint, Firebase
    referencia/                  # payload v3, data dictionary, UPD status contract
    ia-e-agentes/                # AGENTS.md routing idea, how to use AI on the repo
static/img/screens/<tab>/        # PNGs named <tab>-<step>.png
static/video/                    # short clips
i18n/en/  i18n/es/
scripts/check-docs.sh
reference/polaris-heap-main/     # section 3
```
The two top-level areas map to Polaris "areas". Keep the frontmatter and slug rules identical so a later move into Polaris is a folder move plus a sidebar entry.

## 6. Media
- **Screenshots:** PNG, fixed 1440 px browser width, one folder per tab, **demo data only** (no client data). Every image has alt text. Add `docusaurus-plugin-image-zoom`; that is the only extra dependency worth it.
- **Short clips** (under 30 s, no audio, MP4 + WebM): plain `<video controls muted playsinline preload="metadata">` in MDX. Storage is either Git LFS or a GCS bucket behind the same IAP domain. LFS only if the clips stay small; otherwise the bucket.
- **Long walkthroughs:** a small `VideoEmbed` MDX component (lazy `<iframe>`) for unlisted YouTube or Drive links. Access control for these is outside IAP, so never show real client data in them.
- **Translations:** images are shared across locales. The app UI is pt-BR, so screenshots stay pt-BR; only captions are translated.

## 8. Phases
1. **Bootstrap:** new repo, Docusaurus config (3 locales, `noIndex`, theme tokens, local search such as `@easyops-cn/docusaurus-search-local` with all three locales), `check-docs.sh`, Dockerfile + nginx + deploy workflow, domain and IAP, Polaris reference copy.
2. **User guide skeleton:** every page exists in pt-BR with frontmatter, an outline and `:::info Página em construção`, so the build and sidebar are green early.
3. **Capture and write:** run DS30 (`./run_app.sh`) with demo data, capture screenshots and clips per tab, write the guide pages.
4. **Project documentation:** migrate and clean the `Docs/` content (architecture, integrations, reference). Label legacy material.
5. **Translation:** en, then es (`docusaurus write-translations`; AI-assisted draft, then human review).
6. **Polaris readiness check:** run Polaris's `check-docs.sh` against the content in a scratch copy and confirm there are no slug or frontmatter collisions.

## 9. New repo setup (first steps for you)
- Create the repo (suggested `ds30-docs`) with `dev` as the default branch, same git workflow as `gtm_analyzer_app` (task branches, Conventional Commits, merges with `--no-ff`).
- First working branch: `feat/docs-site-bootstrap`.
- Later branches: `feat/user-guide-workspace-tabs`, `docs/translate-es`, and so on.
- Add a `CLAUDE.md` early, based on Polaris's, with the rules from sections 4 and 6.

## 10. Open points
- Domain name for the site (for example `ds30-docs.dp6.io`), plus a GCP project and IAP setup that you approve.
- Video storage: Git LFS or a bucket.
- Final tab list on `dev` (section 7).

## 11. Verification (once built)
- `npm run build` succeeds for all three locales with `onBrokenLinks: 'throw'`.
- `scripts/check-docs.sh` passes in CI on a PR.
- `npm run start -- --locale en` and `--locale es` render, with images and video loading.
- The deployed URL asks for a `dp6.com.br` login (IAP) and returns `X-Robots-Tag: noindex`.
